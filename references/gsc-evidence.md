# GSC evidence for article work

Use this reference for article selection, query/page visibility, CTR or traffic
comparisons, indexing diagnosis, and post-publication effect reviews. Ordinary copy edits and keyword discovery
without a site-performance question do not require a GSC request.

## Read through the project's existing connection

Confirm the exact property from the project profile and observed access. Prefer
the connected GSC MCP read tools. An existing authorized project API/CLI adapter
or its saved output may supply the same evidence when it preserves the property,
dates, dimensions, filters, data state and retrieval limits needed for the claim.
Identify the actual source; do not label a CLI result as an MCP observation.
Installing this skill does not register MCP, authenticate Google, or authorize
new OAuth consent, wider access, sitemap submission or other Google writes.

Use the project's existing secret management. Keep credentials and raw private
query exports out of skill files, Git and public artifacts. Reuse valid reads
from the same account, property, period and parameters.

For a missing connection, report the named
missing boundary. Continue independent work; do not invent metrics, substitute
another site's property, or silently start authentication. A failure or missing
row is not measured zero. Hold any selection or conclusion requiring that data.

## Select the evidence needed for the claim

- Candidate selection: compare page-level performance over identical conditions,
  then inspect query/page rows for plausible candidates. Keep registered target
  queries and observed incoming queries distinct. Query-row sums do not establish
  page totals; obtain page-level aggregates separately when totals are needed.
- Article diagnosis: use the exact page and target/variant queries. GSC average
  position is not a live SERP rank, and impressions are not market search volume.
  Keep keyword-source research and actual SERP observations as separate evidence.
- Indexing: inspect only relevant URLs and preserve indexed status, canonical and
  last crawl time. Inspection is not a live crawl, indexing request or proof that
  an edit has been re-evaluated.
- Effect review: follow the project's publication dates and matched comparison
  windows, excluding the edit day when required. Keep provisional and final
  evaluations separate. Use a default period only when no relevant period was
  specified; it does not replace an existing review schedule.

Use final data with explicit inclusive Pacific dates. Verify available dates;
a fixed lag is not proof of completeness. Bound pagination and report whether
more rows remain. A limited result is not a global ranking or exhaustive list.
GSC does not measure conversions or GA4 landing sessions. Separate observed
changes from hypotheses; a before/after difference alone does not prove causation.

## Match collection to the caller

For standalone blog-agent work, start from the named article and the question
being answered. Reuse its existing evidence, query only the missing page/query
slice, and inspect indexing only when indexing or post-edit crawl state matters.
Do not scan every property or collect a site-wide report for a sentence edit.

For recurring article reviews, first group due reviews and eligible candidates by property,
search type, dimensions, filters and comparison windows. Reuse one read only
where those conditions actually match; retain article-specific filters and edit
windows. Fetch a bounded page-level comparison to shortlist candidates, then
query/page detail for that shortlist. Do not call URL Inspection for every page
by default. Batch only relevant URLs within the connection's limit. Fetch additional
pages when truncation could change candidate selection, within the project's
budget; disclose a remaining sampling limit instead of calling the sample best.
A smoke-test sample is not sufficient evidence for production candidate ranking.

Choose the next observation from the suspected constraint:

| Signal | Useful next evidence | Avoid |
| --- | --- | --- |
| Missing or sharply reduced visibility | Query/page scope, coverage and canonical/crawl state for the affected URL | Prescribing more prose before checking indexing and missing data |
| Impressions with weak CTR | Same query/page and comparable device/country conditions, position and actual SERP features | Treating every low CTR as a title defect |
| Clicks without the intended action | Separately verified GA4 landing-page and event evidence | Inferring conversions from GSC |
| No apparent response after an edit | Available final dates, last crawl, comparable windows and intervening changes | Rewriting again solely because a review date arrived |

Prioritize an eligible article with observed search opportunity and a concrete,
fixable reader-facing deficiency. Explain why it precedes the alternatives;
do not create a universal score, fixed rank threshold or automatic rewrite rule.
When comparing periods, retain previously selected queries and unfavorable
results as well as gains. Fewer calls are useful only while the evidence still
supports the requested selection or conclusion.

## Carry evidence into the article stage

Use the existing research, reviews or project adapter output rather than adding
a separate ledger. Retain the property, retrieval time, source/command, dates,
search type, dimensions, filters, data state, row/page limits, pagination state,
metrics and errors or omissions needed to reproduce the conclusion. Read those locations and the selection rationale before making another request. Refresh only for changed inputs, stale evidence or a
specific missing observation.

GSC informs research and the Codex draft; follow [codex-writing.md](codex-writing.md)
for writing and checks. Preserve user adoption, publication, daily-slot and
scheduling rules. Missing GSC evidence does not authorize a new article where
only existing-article updates were agreed.
