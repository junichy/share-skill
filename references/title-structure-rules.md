# Title And Structure Rules

title、H1、H2/H3、構成を決める時に読む。

## Title guardrails

- 既存の勝ち記事が具体意図で伸びている場合、広い概念 title を優先しない
- まず `条件語` `状況語` `行動語` `一覧語` のどれを拾うか決める
- 主 query は文字列一致ではなく意味順で吸収し、自然な日本語に変換して前半へ置く
- 日本語 title では、主 query を半角スペース区切りで直置きしない
- title は安易に `|` `-` `｜` などの記号で前後をつながない。自然な一文として成立する案を先に作る
- 記号を使うのは、SERP 上位の勝ち title に同じ型があり、かつ記号なしでは日本語が不自然になる場合だけにする
- 重要なSEO記事の title は原則 29-34 文字に収める。短く縮めすぎず、条件語・不安語・行動語・解決語のうちSERPで必要な語を入れる
- キーワードを入れても不自然な日本語になる案は落とす
- 親記事 title は全体像と判断基準を示す。子記事 title は具体不安・条件・行動を前半に置き、親記事の総論 title と同じ型にしない

悪い例:

- 広い総論 title の後半に主 query を添えるだけ
- 低ボリューム query なのに、記事全体の主題を広くする
- SERP が親記事型なのに、低ボリュームの子 query を title 前半に置いて検索意図を狭める
- 親記事と子記事で同じ title 語彙、同じH1、同じ導入の約束を使う
- 競合が専門記事で勝っているのに、自記事は1セクションで回収する
- `前半｜後半` や `前半 - 後半` の形にして、自然な日本語として読めない
- 29文字未満に縮めすぎて、SERPで必要な条件語・不安語・行動語が抜ける

## Title intent patterns

広い概念名だけの title は避け、検索者の状態が見える語を title 前半に置く。

1. `行動直前型`
   - 検索者が「今から何をすればいいか」を探している状態
   - 使う語: `どこから` `いつから` `申し込み方法` `申し込み方` `流れ` `始め方` `やり方` `準備`
   - 例: `インターンの申し込み方法と始め方の流れ`
2. `状況不安型`
   - 検索者が「大丈夫か」「失敗しないか」「自分でもできるか」を探している状態
   - 使う語: `怖い` `きつい` `意味ない` `落ちる` `不安` `失敗` `間に合う` `ギリギリ` `やめとけ`
   - 後半は煽りで終わらせず、`理由` `対策` `判断` などに落とす
3. `条件指定型`
   - 検索者が条件つきで探している状態
   - 使う語: `登録不要` `無料` `大学1年生` `未経験` `週2日` `地域名` `例文`
4. `比較一覧型`
   - 検索者が選びたい、比べたい状態
   - 使う語: `おすすめ` `比較` `ランキング` `○選` `一覧` `違い`

実務ルール:

- title 前半は `対象 + 行動/不安/条件` にする
- title 後半は `得られる答え` `判断材料` `対策` にする
- GSC や SERP で確認できる検索者の実語彙を優先する
- 同じ意味なら、事業者側の言い方より検索者側の言い方を使う
- 広い概念 title は、具体意図で勝てる根拠がある場合だけにする

## Winning pattern analysis

既存の勝ち記事がある場合は、検索意図だけでなく `何の型で勝っているか` まで分類する。

- 伸びている記事の主 query を確認する
- 次を分けて見る
  - `広いテーマ` で勝っているのか
  - `条件つきの具体意図` で勝っているのか
- 勝ち query を次の型に分類する
  - `条件指定型`: `登録不要` `無料` `例文`
  - `状況不安型`: `しない` `時間がない` `怖い`
  - `行動直前型`: `どこから` `いつから` `やり方`
  - `比較一覧型`: `ランキング` `○選` `比較`
  - `地域条件型`: `名古屋` `東海`
- 負けている記事では、意図が広すぎないか、条件語が弱くないかを見る

出力すること:

- `勝ち記事`
- `勝ちクエリ`
- `勝ち型`
- `再現すべき条件語`
- `避けるべき広すぎる切り口`

## Competitive structure design

構成では次を作る。

- 導入
- H2 を 3-4 個
- 必要な H3
- まとめ

構成を出す前に、research に `Top 10 -> Article Structure Rationale` を書く。上位10件のどの evidence から各 H2/H3 が必要になったのか、採用しない要素はなぜ外すのか、親記事・子記事・内部リンク先へ逃がす要素は何かを明記する。

各H2/H3の最終案では、その見出しが受け持つ検索意図に対応するSERPを確認する。主queryの調査で同じ意図まで読めていればその結果を再利用し、別の疑問・条件・行動を扱う見出しには対応するqueryを調べる。取得元・日時・上位ページの答え方と採否の理由を残す。同義の見出しごとに検索を増やさず、競合の見出し文言もそのまま写さない。

各セクションに持たせること:

- セクション意図
- 差別化ポイント
- 入れる keyword
- 目標文字数配分
- どの勝ち型を本文で回収するか
- 根拠になった organic rank
